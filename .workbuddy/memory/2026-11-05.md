# 2026-11-05

## Cloudflare 部署对接（tech-arena）

架构定案：单一 Worker 同时托管前端与 API，不用 Pages。
- `worker/wrangler.jsonc`：`assets.directory = ../demo/public` + `run_worker_first: ["/api/*"]`，D1 绑定 `DB` → `techarena-leads`，需填真实 `database_id`。
- 前端 `demo/public/index.html` 的所有请求都是相对路径 `/api/*`，同域即通，无需 CORS。
- `demo/server.js` 保留为纯前端本地 mock（数据在 `demo/data/users.jsonl`）；完整链路用 `wrangler dev`（本地 D1 在 `worker/.wrangler/`）。
- 后台令牌：生产用 `wrangler secret put ADMIN_TOKEN`，本地用 `worker/.dev.vars`（已 gitignore）。前端底部链接改为点击时询问令牌并存 localStorage（key `ta_admin_token`）。
- `worker/schema.sql` 增加 `uniq_users_username`（lower(username) 唯一索引），配合 Worker 现有的 UNIQUE 错误兜底。
- npm scripts：`dev` / `deploy` / `tail` / `db:init` / `db:init:remote` / `db:sql` / `test`。
- 部署步骤写在根目录 `DEPLOY.md`。

环境注意：本机 npm 首次安装 wrangler 时 esbuild/postinstall 报 EBUSY、且缺 `@cloudflare/workerd-windows-64`，需 `npm i --no-save @cloudflare/workerd-windows-64 @esbuild/win32-x64` 补装；`node_modules/.bin/cf-wrangler` 是受限包装器（仅 dev/build），要用 `wrangler` 或 `node node_modules/wrangler/bin/wrangler.js`。

验证：`node test.mjs` 14/14 通过；本地 `wrangler dev` 下 /api/health、注册、重复校验 409、未授权 401、CSV 导出 200 均正常。
